Exemplos resolvidos — Módulo 1 (obrigatório: 3 por unidade, natureza distinta)

Conforme Seção 5.4 do prompt mestre: introdução, aplicação prática, interpretação de erro. Aqui, 3 exemplos para a unidade 1.2 Word.

Exemplo 1 (introdução) — Criar sumário automático

Problema: documento com capítulos "1. Introdução", "2. Desenvolvimento", "3. Conclusão".
Passos:
  1. Aplicar estilo "Título 1" a cada capítulo.
  2. Posicionar cursor no início.
  3. Referências → Sumário → Sumário Automático 1.
  4. Atualizar via "Atualizar campo" quando capítulos mudarem.
Resultado: sumário com links internos e numeração automática.
Erro comum: aplicar formatação direta (negrito, tamanho) sem estilo; o sumário não reconhece o capítulo.

Exemplo 2 (aplicação prática) — Cabeçalhos diferentes por seção

Problema: relatório técnico com capa (sem cabeçalho), corpo (título no cabeçalho), anexos (numeração romana).
Passos:
  1. Inserir Quebra de Seção (Next Page) após capa.
  2. Em cada seção, desmarcar "Vincular ao anterior" no cabeçalho.
  3. Inserir cabeçalho específico (título do capítulo no corpo; "Anexo A" nos anexos).
  4. Configurar numeração de páginas por seção (romana vs arábica).
Resultado: documento com formatação independente por seção, conforme norma ABNT.
Erro comum: usar quebra de página em vez de seção; cabeçalho persiste igual em todo documento.

Exemplo 3 (interpretação de erro) — Sumário vazio após atualização

Problema: após atualizar o sumário, aparece "Nenhuma entrada de sumário encontrada."
Diagnóstico:
  - Verificar se os capítulos têm estilo "Título 1" aplicado (não apenas formatação direta).
  - Confirmar que o campo do sumário está inserido (não texto estático copiado manualmente).
Correção: reaplicar estilos; excluir sumário antigo; inserir novo via Referências > Sumário.
Justificativa técnica: o sumário usa campos de referência baseados em estilos, não em texto arbitrário.

Exemplos resolvidos — Módulo 1.3 Excel 3 EXEMPLOS / SIMULADOR DOCUMENTADO

Conforme Seção 5.4 (exemplos resolvidos) e 7.1 (simuladores). Nenhum resultado inventado: cada exemplo usa cálculos consistentes com o escopo do simulador (`assets/js/simulators.js`). Limitações documentadas explicitamente.

Exemplo 1 (introdução) — Cálculo de média, máximo e mínimo de notas

Problema: planilha com notas 7,5; 8,0; 6,5; 9,0; 8,5. Calcular média, máximo e mínimo.
Funções aplicáveis (simulador): MÉDIA, MÁXIMO, MÍNIMO.
Execução (simulador):
  MÉDIA(7.5, 8, 6.5, 9, 8.5) => (7.5+8+6.5+9+8.5)/5 = 39.5/5 = 7.9
  MÁXIMO(...) => 9
  MÍNIMO(...) => 6.5
Resultado esperado: média 7,9; máximo 9,0; mínimo 6,5.
Nota técnica: separador decimal é vírgula no Excel pt-BR; o simulador aceita tanto vírgula quanto ponto na entrada e converte internamente. Não aceita intervalos externos fora do escopo.
Limite documentado: o simulador não aceita nomes definidos, tabelas estruturadas nem referências a outros arquivos (rejeição com mensagem iniciada por "ERRO DE ENTRADA"); fórmulas aninhadas são processadas pelo parser recursivo (sem `eval`).

Exemplo 2 (aplicação prática) — Função SE com múltiplas condições

Problema: classificar nota 7,5 como "Aprovado" (se >=7) ou "Reprovado" (se <7).
Função: SE.
Execução (simulador):
  SE(7.5 >= 7, "Aprovado", "Reprovado") => "Aprovado"
  SE(6.0 >= 7, "Aprovado", "Reprovado") => "Reprovado"
Justificativa técnica: SE avalia a condição lógica e retorna o segundo argumento se verdadeira, o terceiro se falsa. É a base para classificações, cálculos condicionais e filtros lógicos.
Erro comum: inverter ordem dos argumentos — colocar mensagem antes da condição, o que produz resultado incorreto sem aviso claro (o Excel retorna 0 ou texto inesperado).

Exemplo 3 (interpretação de erro / limitação) — Erro de execução × rejeição de entrada

Problema: usuário digita SOMASE(10; "texto"; 20) — o 1º argumento de SOMASE deve
ser um intervalo (ex.: A1:B5); um número no lugar do intervalo é erro de uso.
Comportamento real do simulador (saídas executadas em Node em 2026-10-20):
  - SOMASE(10; "texto"; 20) => #VAL! com detalhe "SOMASE exige um intervalo —
    esperado um intervalo (ex.: A1:B5) ou lista de valores" — erro de EXECUÇÃO:
    a fórmula foi aceita e avaliada; o retorno usa o código #VAL!, não "ERRO DE ENTRADA".
  - Entradas fora do escopo são recusadas ANTES da avaliação, com mensagem que
    começa com "ERRO DE ENTRADA". Exemplo verificado: MINHA_TABELA+1 =>
    "ERRO DE ENTRADA [calcularFormula] — nome "MINHA_TABELA" não reconhecido —
    nomes definidos e tabelas estruturadas estão fora do escopo documentado".
  - Fórmulas aninhadas são ACEITAS (parser recursivo próprio, sem eval).
  - PROCX/PROCH/PROCV executam busca real nos intervalos informados (exata e
    aproximada); na ausência de correspondência devolvem o código #N/A — no PROCX,
    alternativamente o valor de "se_não_encontrado".
Correção: passar um intervalo (e não um número) a SOMASE/CONT.SE/MÉDIASE;
conferir o separador regional (";" separa argumentos no modo pt-BR; vírgula ou
ponto decimais); e consultar o escopo documentado no cabeçalho de simulators.js
antes de usar nomes definidos, tabelas estruturadas ou sintaxe de outra região.
